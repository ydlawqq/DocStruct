# DocStruct

Сервис извлечения структурированных данных из чеков и документов на базе мультимодальной модели **Qwen2-VL-2B-Instruct**, дообученной под задачу с помощью **LoRA (QLoRA)**.

Проект состоит из трёх независимых частей:

- **Обучение** — дообучение модели на датасете чеков, результат — PEFT-адаптер;
- **Инференс** — HTTP-сервис на FastAPI, который по изображению возвращает структурированный JSON;
- **Веб-интерфейс** — чат-бот на Chainlit для загрузки изображений, просмотра результата и сохранения чеков в PostgreSQL.

## Возможности

- Извлечение данных из чеков: на вход — изображение, на выходе — JSON (позиции, суммы, итоги);
- LoRA-дообучение (QLoRA): 4-bit квантование + low-rank адаптеры, экономия памяти и времени;
- Инференс как отдельный сервис: FastAPI + асинхронная очередь, независимость от БД;
- Веб-интерфейс на Chainlit: загрузка изображения через чат, ответ модели прямо в браузере;
- **Сохранение распознанных чеков в PostgreSQL** с привязкой к пользователю;
- **Параллельные сессии пользователей** — каждый пользователь видит и сохраняет свои чеки отдельно;
- Совместимость с CPU: автоматический fallback на `float16` при отсутствии CUDA;
- Готовая конфигурация Docker Compose: подъём всего стека одной командой (CPU/GPU).

## Архитектура

```
┌──────────────────────┐       ┌───────────────────────────────┐
│   Обучение (QLoRA)   │       │    Инференс (FastAPI)         │
│                      │       │                               │
│  dataset → trainer   │       │  POST /extract                │
│  → adapters/         │──────>│  └─> InferenceQueue ─> model  │
└──────────────────────┘       │  └─> JSON-ответ              │
                               └───────────────┬───────────────┘
                                               │
                                               ▼
                               ┌───────────────────────────────┐
                               │    Веб-интерфейс (Chainlit)    │
                               │  загрузка изображения в чат    │
                               │  → POST /extract → результат   │
                               │  → сохранение в PostgreSQL     │
                               └───────────────┬───────────────┘
                                               │
                                               ▼
                               ┌───────────────────────────────┐
                               │    PostgreSQL (сервис db)      │
                               │  users / receipts             │
                               └───────────────────────────────┘
```

- **Обучение** отделено от инференса: результатом обучения является каталог адаптеров (`adapters/qwen2vl-2b`), который инференс подхватывает при старте.
- **Инференс** — автономный сервис: принимает изображение, возвращает JSON и не выполняет запись в БД (персистентность — ответственность клиента/прослойки).
- **Очередь** (`InferenceQueue`) выполняет тяжёлую генерацию в отдельном потоке, не блокируя event loop FastAPI.
- **Chainlit** — веб-интерфейс: пользователь прикрепляет изображение к сообщению, Chainlit отправляет его на `POST /extract`, показывает ответ модели в чате и **сохраняет распознанный чек в PostgreSQL**.
- **PostgreSQL** — хранит пользователей и их чеки. Chainlit подключается к нему по внутренней docker-сети (хост `db`).

## База данных

Проект использует **PostgreSQL 15** для хранения пользователей и распознанных чеков.

### Модели

**`users`** — пользователи чата:

| Поле          | Тип      | Описание                                    |
|---------------|----------|---------------------------------------------|
| `id`          | int      | Первичный ключ (автоинкремент)              |
| `external_id` | str      | Уникальный идентификатор из Chainlit (email/username) |
| `country`     | str      | Страна пользователя                         |
| `firs_call`   | datetime | Время первого обращения                     |

**`receipts`** — распознанные чеки:

| Поле        | Тип      | Описание                                    |
|-------------|----------|---------------------------------------------|
| `id`        | int      | Первичный ключ (автоинкремент)              |
| `time`      | datetime | Время распознавания                         |
| `user_id`   | int      | FK → `users.id` (CASCADE)                   |
| `shop_name` | str      | Название магазина                           |
| `total`     | float    | Сумма чека                                  |
| `products`  | JSON     | Полный JSON-ответ модели (позиции и пр.)    |

### Как это работает

1. При старте чата (`on_chat_start`) Chainlit создаёт таблицы (если их нет) и upsert-ит пользователя по `external_id`.
2. После распознавания чека (`on_message`) Chainlit сохраняет результат в таблицу `receipts`, привязывая его к `user_id`.
3. Параллельные сессии разных пользователей разводятся по `external_id` — каждый видит и сохраняет свои чеки отдельно.

### Подключение

Chainlit подключается к PostgreSQL по внутренней docker-сети (хост `db`), а не через `localhost`. Переменные окружения:

| Переменная | Описание                          |
|------------|-----------------------------------|
| `DB_HOST`  | Хост БД (в compose — `db`)        |
| `DB_USER`  | Пользователь БД                   |
| `DB_PASS`  | Пароль БД                         |
| `DB_NAME`  | Имя БД                            |
| `DB_PORT`  | Порт БД (внутри сети — `5432`)    |

> **Примечание.** Если таблицы уже существовали в БД без колонки `external_id`, нужно удалить volume БД (`docker compose down -v`) или выполнить миграцию вручную, т.к. `create_all` не добавляет колонки в существующие таблицы.

## Обучение (QLoRA)

### Пайплайн

1. **Датасет**: `mychen76/ds_receipts_v2_test` (HuggingFace) — колонки `image` и `text`.
   Код подготовки: `training/data/prepare_dataset.py`.
2. **Предобработка целевого поля**: из JSON удаляются поля `tax`, `subtotal`, `ignore`, `tips`, а из позиций — `item_key`.
3. **Разбиение**: 90% train / 10% val.
4. **Квантование**: 4-bit `BitsAndBytes` (nf4 + double quant) — режим QLoRA.
5. **LoRA**: адаптеры на `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`.
6. **Маскирование промпта**: токены пользовательской части исключаются из loss — модель обучается только на ответе ассистента.
7. **Early stopping**: `patience=1`, `threshold=0.1`.
8. **Результат**: PEFT-адаптер сохраняется в `adapters/qwen2vl-2b` и используется инференсом.

---

### Запуск

```bash
# из корня проекта
train --config src/configs/qwen2_2b.yaml
```

### Ключевые параметры конфига

| Секция        | Параметр           | Значение по умолчанию               | Описание                              |
|---------------|--------------------|-------------------------------------|---------------------------------------|
| `model`       | `name`             | `Qwen/Qwen2-VL-2B-Instruct`         | Базовая модель                       |
| `model`       | `adapters_dir`     | `adapters/qwen2vl-2b`               | Каталог сохранения/чтения адаптера   |
| `quantization`| `load_in_4bit`     | `true`                              | 4-bit квантование (только NVIDIA GPU)|
| `lora`        | `r` / `alpha`      | `16` / `32`                         | Ранг и масштаб LoRA                  |
| `lora`        | `target_modules`   | `[q,k,v,o,gate,up_proj]`            | Целевые слои                          |
| `training`    | `num_train_epochs` | `3`                                 | Число эпох                            |
| `training`    | `learning_rate`    | `2e-5`                              | Скорость обучения                     |
| `training`    | `output_dir`       | `adapters/qwen2vl-2b`               | Каталог адаптера                      |

> **Примечание.** QLoRA (4-bit) требует NVIDIA GPU. Обучение на CPU не предусмотрено.

## Взаимодействие с Chainlit

Chainlit — веб-интерфейс в виде чат-бота. Он позволяет загружать изображение чека прямо в браузер, получать результат распознавания от модели и сохранять его в БД.

### Как это работает

1. Пользователь открывает `http://localhost:8001` и отправляет сообщение с прикреплённым изображением чека.
2. Chainlit (`frontend/app.py`) находит прикреплённое изображение в сообщении.
3. `frontend/client.py` отправляет его на `POST /extract` сервиса инференса (`MODEL_URL`).
4. FastAPI обрабатывает изображение через очередь и возвращает JSON.
5. Chainlit показывает результат в чате и **сохраняет чек в PostgreSQL** (пользователь + чек).

### Ключевые файлы

| Файл                 | Назначение                                              |
|----------------------|---------------------------------------------------------|
| `frontend/app.py`    | Обработчики событий Chainlit + запись в БД              |
| `frontend/client.py` | HTTP-клиент к инференсу (отправка файла, таймаут 600 с) |
| `frontend/db/`       | Слой работы с PostgreSQL (модели, репозитории)          |
| `frontend/Dockerfile`| Сборка образа chainlit                                  |
| `frontend/requirements.txt` | Зависимости: chainlit, httpx, sqlalchemy, asyncpg |

### Переменные окружения chainlit

| Переменная   | По умолчанию           | Описание                                   |
|--------------|------------------------|--------------------------------------------|
| `MODEL_URL`  | `http://inference:8000`| Базовый URL сервиса инференса              |
| `CHAINLIT_PORT` | `8001`              | Хост-порт, на котором доступен интерфейс   |
| `DB_HOST`    | `db`                   | Хост PostgreSQL (внутри docker-сети)       |
| `DB_USER`    | из `.env`              | Пользователь БД                            |
| `DB_PASS`    | из `.env`              | Пароль БД                                  |
| `DB_NAME`    | из `.env`              | Имя БД                                     |
| `DB_PORT`    | `5432`                 | Порт БД                                    |

### Использование

1. Убедись, что инференс готов: `curl localhost:8000/health` → `{"status":"ok"}`.
2. Открой `http://localhost:8001`.
3. Прикрепи изображение чека к сообщению и отправь.
4. Дождись ответа — на CPU генерация занимает десятки секунд.
5. Чек автоматически сохранится в PostgreSQL.

> **Примечание.** Если отправить сообщение без изображения, Chainlit ответит «Пришли фотографию!».

## API

### `GET /health`

Проверка готовности сервиса. Отвечает `200` только после загрузки модели.

```bash
curl localhost:8000/health
```

```json
{"status":"ok"}
```

### `POST /extract`

Принимает изображение чека (multipart/form-data) и возвращает распознанный JSON.

```bash
curl -X POST localhost:8000/extract \
  -F "file=@/путь/к/чеку.jpg" \
  -o result.json -w "HTTP %{http_code}\n"
```

Ответ — JSON с извлечёнными данными (состав полей зависит от датасета обучения):

```json
{
  "result": {
    "store_name": "Магазин",
    "store_addr": "ул. Ленина, 1",
    "telephone": "+7...",
    "date": "2024-01-01",
    "time": "12:00",
    "total": "123.45",
    "line_items": [
      {"item_name": "Хлеб", "item_value": "30.00", "item_quantity": "1"}
    ]
  }
}
```

Приоритет пути к конфигу:

1. явный флаг `--config`;
2. переменная `CONFIG_PATH`;
3. значение по умолчанию `src/configs/qwen2_2b.yaml`.

## Тестирование

Проект покрыт unit-тестами на `pytest`. Запускаются из корня проекта.

### Запуск тестов

```bash
# все быстрые тесты (без загрузки модели)
pytest

# только медленные тесты (загрузка модели + адаптеры)
pytest -m slow

# конкретный файл
pytest src/tests/config_test.py
```

### Тестовые файлы

| Файл                       | Что покрывает                                                  |
|----------------------------|-----------------------------------------------------------------|
| `src/tests/config_test.py` | Загрузка YAML-конфига, корректность значений (модель, LoRA, квантование, обучение) |
| `src/tests/dataset_utils_test.py` | Обработка датасета: `_target_change` (удаление `tax`, `subtotal`, `item_key`), `_make_messages` (структура сообщений для модели) |
| `src/tests/collators_test.py`    | Коллаторы обучения и оценки: маскирование pad/image-токенов, `add_generation_prompt` |
| `src/tests/utils_test.py`        | `JSONTrainer`: метрика `json_valid_rate`, `evaluation_loop`, `get_eval_dataloader` |
| `src/tests/model_test.py`        | (slow) Генерация модели: валидность и структура JSON-ответа |

### Маркеры

- `default` (без маркера) — быстрые тесты, не требуют GPU и загрузки модели;
- `slow` — интеграционный тест: загружает реальную модель `Qwen2-VL-2B-Instruct` с адаптерами. Требует GPU и наличия `adapters/qwen2vl-2b`.
